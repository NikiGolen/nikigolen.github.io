Query-Time Schema Fallback (QSF)

Exploring how an intermediate middleware layer handles schema degradation and missing attributes at query time rather than relying strictly on upstream feed validation.

The root cause

Real product feeds don't always fill in every field. One record here never got an isWireless value at all, it's just null. A search for "wireless" or "wired" has nothing to check against for that row, so it normally vanishes from results. This is the catalog exactly as it comes in, from catalog-schema.json.

The problem

Negative queries like "not wireless" or "wired" break rigid boolean filters. If the DB flag is missing, most engines either hide the record or throw. A real product just drops out of results, silently.

The approach

QSF catches the query before it hits the filter. When the flag is null, it falls back to tags like #corded or #wired to resolve it, and logs exactly how it got there instead of guessing quietly.
